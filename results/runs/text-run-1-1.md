1. **SRP — принцип единственной ответственности (3 нарушения)**
   - `createBooking` разбирает HTTP-запрос, проверяет правила бронирования и управляет транзакцией. Изменения формата запроса, правил пересечения и механизма блокировки затрагивают одну функцию.
   - `listBookings` обрабатывает параметры HTTP-запроса, формирует SQL и преобразует строки БД в ответ. Изменения API списка и схемы хранения затрагивают один обработчик.
   - `deleteBooking` проверяет идентификатор из URL, выполняет мягкую отмену и выбирает HTTP-статус по числу обновлённых строк. Правила отмены и контракт HTTP приходится менять в одной функции.

2. **OCP — принцип открытости и закрытости (2 нарушения)**
   - `createBooking` задаёт правило пересечения прямо в SQL. Чтобы поддержать настраиваемый перерыв между бронированиями для отдельных комнат, придётся изменить существующую проверку конфликта в обработчике.
   - `listBookings` выбирает между двумя готовыми SQL-запросами для списка с фильтром по комнате и без него. Чтобы добавить независимый фильтр по пользователю, придётся изменить существующую логику выбора и построения запроса.

3. **LSP — принцип подстановки Барбары Лисков (0 нарушений)**
   - Проект не объявляет собственных интерфейсов с взаимозаменяемыми реализациями. В проверенных вызовах стандартных интерфейсов `http.Handler`, `http.ResponseWriter` и `sql.Result` несовместимых ожиданий не выявлено.

4. **ISP — принцип разделения интерфейсов (0 нарушений)**
   - Обработчики используют все три метода `http.ResponseWriter` напрямую или через функции ответа. `deleteBooking` также получает стандартный `sql.Result` и использует только `RowsAffected`, который нужен для определения результата отмены.

5. **DIP — принцип инверсии зависимостей (3 нарушения)**
   - `createBooking` напрямую использует `*sql.DB`, SQL-транзакцию и консультативную блокировку PostgreSQL. Замена способа хранения или блокировки потребует менять HTTP-обработчик создания брони.
   - `listBookings` напрямую выполняет SQL через `*sql.DB` и считывает `*sql.Rows`. Подключение другого источника списка потребует переписать получение данных внутри HTTP-обработчика.
   - `deleteBooking` привязывает результат отмены к SQL-обновлению `canceled_at` и числу затронутых строк. Замена механизма хранения отмен потребует менять обработчик.

**Итоговое соответствие SOLID — 40%.** Все пять принципов имеют одинаковый вес, по 20 процентных пунктов. Балл начисляется за принцип без выявленных нарушений. По этой шкале проект выполняет два принципа из пяти — LSP и ISP.
