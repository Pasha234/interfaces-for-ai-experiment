1. **SRP — принцип единственной ответственности (3 нарушения)**

   - `Handler.create` разбирает HTTP-запрос и повторяет правила `BookingService.Create` для обязательных идентификаторов и порядка границ интервала. Изменение этих правил требует синхронной правки двух слоёв, иначе HTTP может отклонить данные, которые сервис уже принимает.
   - Модуль `service` ведёт сценарий создания бронирования и реализует побайтовое формирование UUID v4 в `newID`. Изменение формата идентификатора затрагивает модуль бизнес-логики.
   - Модуль `postgres` выполняет операции с бронированиями и управляет схемой через `Migrate`. Изменения схемы, например добавление индекса, затрагивают модуль репозитория даже при прежнем поведении его методов.

2. **OCP — принцип открытости и закрытости (3 нарушения)**

   - `Handler.bookings` задаёт допустимые методы отдельно в диспетчеризации и в заголовке `Allow`. При добавлении `HEAD /bookings` придётся обновить существующий обработчик ответа `405`, даже если маршрут зарегистрировать отдельно.
   - `Handler.booking` жёстко задаёт `DELETE` как единственный допустимый метод. При добавлении `GET /bookings/{id}` придётся изменить существующую обработку `405`, чтобы она сообщала оба доступных метода.
   - `List` принимает единственный критерий `roomID` на всём пути от HTTP до PostgreSQL. Добавление независимого фильтра по `user_id` потребует изменения сигнатур обоих используемых интерфейсов, обработчика, сервиса и SQL-запроса.

3. **LSP — принцип подстановки Барбары Лисков (2 нарушения)**

   - `BookingService.Create` принимает интервалы с наносекундными границами, а PostgreSQL-реализация `BookingRepository.Create` хранит время с точностью до микросекунды. Короткий интервал может схлопнуться при записи и вызвать HTTP 500, а после успешного создания `List` может вернуть границы, отличные от полученных при создании. [Документация PostgreSQL о типах даты и времени](https://www.postgresql.org/docs/18/datatype-datetime.html)
   - `BookingRepository.Create`, `List` и `Delete` передают текстовые идентификаторы в PostgreSQL, хотя вызывающие слои пропускают строки с символом NUL, который тип `text` не поддерживает. В результате создание и фильтрация могут завершиться HTTP 500, а отмена по отсутствующему идентификатору — вернуть HTTP 500 вместо ожидаемого `404`. [Документация PostgreSQL о строковых типах](https://www.postgresql.org/docs/18/datatype-character.html)

4. **ISP — принцип разделения интерфейсов (0 нарушений)**

   `Handler` использует все методы `httpapi.BookingService`, а сервис использует все методы `domain.BookingRepository`. У `domain.BookingService` потребителей в текущем проекте нет.
